# Обязательный Git-процесс проекта

Этот порядок работы обязателен для каждой задачи в проекте.

## Начало новой задачи

1. Новая задача начинается только от актуальной и чистой ветки `main`.
2. Перед началом работы необходимо синхронизировать локальный `main` с удалённым репозиторием.
3. Для каждой новой задачи создаётся отдельная рабочая ветка от `main` с именем вида `work/<название-задачи>`.
4. Нельзя начинать новую задачу непосредственно в `main` или продолжать её в ветке предыдущей задачи.

## Завершение задачи

1. Проверить выполненную работу и состояние репозитория.
2. Зафиксировать изменения коммитом в рабочей ветке.
3. Отправить рабочую ветку на GitHub командой `push`.
4. После `push` остановиться и сообщить пользователю, что ветка готова к проверке и объединению.

## Pull Request и Merge

1. Pull Request создаёт пользователь самостоятельно.
2. Merge выполняет пользователь самостоятельно.
3. Агенту запрещено создавать Pull Request или выполнять Merge без отдельного прямого запроса пользователя.
4. До сообщения пользователя об успешном Merge агент не синхронизирует завершённую работу с `main` и не начинает следующую задачу.

## Действия после подтверждения Merge

После того как пользователь сообщил, что Merge выполнен, необходимо:

1. Переключиться на `main`.
2. Получить актуальное состояние удалённого репозитория.
3. Обновить локальный `main` безопасным fast-forward обновлением.
4. Убедиться, что локальный `main` совпадает с удалённым и рабочее дерево чистое.
5. Удалить завершённую локальную рабочую ветку.
6. Остаться на чистой и актуальной ветке `main`.

Удаление удалённой рабочей ветки выполняет пользователь на GitHub, если он считает это необходимым.

## Следующая задача

Следующая задача начинается только после подтверждённого Merge, синхронизации `main` и создания новой рабочей ветки от актуального `main`.
