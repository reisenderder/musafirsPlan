# Telegram-сборщик: установка и эксплуатация WP-003

WP-003 принимает материалы из разрешённых Telegram-групп и от родителей,
сохраняет их локально и публикует карточки в закрытой группе отбора. Анализ,
адаптация, PDF и семейный учебный бот появятся в WP-004–WP-007.

## Что уже работает

- облачный Telegram Bot API через long polling без публичного сервера;
- фильтр до 10 разрешённых групп и до двух родителей;
- документы, изображения, содержательные тексты и ссылки;
- регистрация аудио/видео без скачивания и распознавания;
- скачивание файлов до 20 МБ и ручной импорт более крупных файлов;
- SQLite-очередь, SHA-256-дедупликация и локальное файловое хранилище;
- карточки отбора и действия `Взять`, `Не брать`, `Отложить`, `Подробнее`;
- журнал действий и выявление противоположных решений родителей;
- команды локального просмотра очереди для пользователя и Codex.

## 1. Подготовка Telegram

1. В официальном `@BotFather` создать бота-сборщика командой `/newbot`.
2. Там же создать отдельного бота-издателя. Его токен в WP-003 можно пока не
   указывать: бот начнёт публиковать семейные материалы в WP-006.
3. Создать закрытую группу `Отбор материалов`, добавить туда обоих родителей и
   бота-сборщика.
4. Добавить сборщика в каждую разрешённую группу-источник. Чтобы он видел
   обычные сообщения, назначить его администратором либо отключить Privacy Mode
   через `/setprivacy` в BotFather.
5. Не пересылать токены в групповые чаты и не сохранять их в GitHub.

## 2. Локальная конфигурация

Требуется Python 3.11 или новее. В корне проекта:

```powershell
Copy-Item .env.example .env
```

Сначала вставить в `.env` только `MUSAFIRS_COLLECTOR_BOT_TOKEN`. Написать боту в
личном чате, а также отправить короткое контрольное сообщение в группе отбора и
каждой группе-источнике. Затем посмотреть ID:

```powershell
.\telegram\collector.ps1 discover
```

Заполнить в `.env`:

- `MUSAFIRS_ALLOWED_SOURCE_CHAT_IDS` — ID разрешённых групп через запятую;
- `MUSAFIRS_PARENT_USER_IDS` — Telegram ID одного или двух родителей;
- `MUSAFIRS_REVIEW_CHAT_ID` — ID закрытой группы отбора;
- `MUSAFIRS_PUBLISHER_BOT_TOKEN` — необязательный токен будущего издателя.

Файл `.env` исключён из Git. Папка `var/` с базой и личными материалами также не
попадает в репозиторий.

## 3. Первый запуск

Создать локальные каталоги и базу:

```powershell
.\telegram\collector.ps1 init
```

Проверить конфигурацию и связь с Telegram:

```powershell
.\telegram\collector.ps1 doctor
```

Запустить сборщик:

```powershell
.\telegram\collector.ps1 run
```

Окно PowerShell должно оставаться открытым. После перезагрузки или длительного
выключения компьютера команда `run` запускается повторно вручную.

## 4. Работа с материалами

Новый подходящий материал из разрешённой группы появляется карточкой в группе
отбора. Решение одного родителя достаточно. Если родители дали противоположные
решения, карточка получает статус `Требует совместного решения`. Когда один из
родителей изменит голос и решения совпадут, конфликт снимается.

Просмотреть локальную очередь без Telegram:

```powershell
.\telegram\collector.ps1 list
```

Просмотреть журнал решений:

```powershell
.\telegram\collector.ps1 audit
```

Для расширенного просмотра доступны команды Python:

```powershell
$env:PYTHONPATH = "src"
python -m musafirs_bot list --status approved --limit 20
python -m musafirs_bot show 1
python -m musafirs_bot audit --limit 200
```

## 5. Файлы больше 20 МБ и пропуски после простоя

Файл больше 20 МБ сохранить вручную в:

```text
var/telegram/inbox/manual/
```

Сборщик проверяет папку во время работы. Немедленная проверка запускается так:

```powershell
.\telegram\collector.ps1 import-manual
```

Исходный файл из папки не удаляется. Сервис копирует его в управляемое хранилище
и пропускает повторное содержимое по SHA-256.

Если компьютер не работал больше 24 часов, пропущенные сообщения нужно вручную
переслать сборщику. Сам бот не может восстановить старую историю группы.

## 6. Локальные данные и перенос на другой компьютер

По умолчанию данные находятся в `var/telegram/`:

```text
ingestion.sqlite3       очередь и журнал решений
files/<ID>/             сохранённые материалы
inbox/manual/           ручной входящий каталог
```

Для нового компьютера:

1. Клонировать GitHub-репозиторий.
2. Установить Python 3.11+.
3. Восстановить `.env` из своего безопасного локального хранилища либо заполнить
   его заново.
4. Скопировать резервную копию каталога данных.
5. Выполнить `collector.ps1 doctor`, затем `collector.ps1 run`.

Резервное копирование каталога данных пользователь выполняет самостоятельно.

## 7. Проверка разработки

Тесты не обращаются к Telegram и не используют реальные токены:

```powershell
$env:PYTHONPATH = "src"
python -m unittest discover -s tests -v
```
