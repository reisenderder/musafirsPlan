## Исходный запрос

Подключить Telegram-бота, которому можно отправлять текст, PDF-книги и другие
файлы. Материалы должны становиться доступными агенту для последующей обработки,
а взаимодействие с Telegram должно выполняться через API.

## Фаза 1 — Анализ

### Понимание задачи

Требуется не только бот-получатель, но и безопасный мост между Telegram,
хранилищем полученных материалов и инструментами, которыми может пользоваться
Codex.

### Предварительная архитектура

```text
Telegram → бот-приёмник → защищённое хранилище → инструменты доступа для Codex
```

Предложенный первый этап:

1. Создать бота через BotFather.
2. Ограничить доступ разрешённым Telegram ID.
3. Принимать текстовые сообщения и документы.
4. Сохранять оригинальный файл, подпись, дату, тип и идентификатор сообщения.
5. Вести очередь со статусами `новый`, `обработан`, `ошибка`.
6. Предоставить агенту команды чтения очереди и материалов.
7. Не хранить токены и личные входящие файлы в Git.

Для начальной версии предложен long polling без публичного сервера. Для прямого
доступа агента предложен отдельный локальный интерфейс или MCP-инструменты.

### Риски и ограничения

- Стандартный Telegram Bot API позволяет боту скачивать через `getFile` файлы
  размером до 20 МБ; для более крупных книг потребуется другое решение.
- Необработанные обновления Telegram хранятся не более 24 часов.
- Локальный бот недоступен, когда компьютер выключен.
- Сканированные PDF могут потребовать отдельного OCR.
- Нужны строгая проверка отправителя и безопасное хранение токена.
- Автоматическая обработка моделью потребует отдельной архитектуры и, возможно,
  OpenAI API; обычное получение файлов этого не обеспечивает.
