# Журналы обсуждений

Каталог хранит структурированную историю анализа, вопросов, решений и реализации
по каждой самостоятельной работе проекта.

## Связь с другими документами

- `WORK_PLANS.md` отвечает на вопрос: «Что сейчас делается и в какой ветке?»
- Журнал обсуждения отвечает на вопрос: «Что обсуждали, почему решили именно так
  и на чём остановились?»
- `CHANGELOG.md` отвечает на вопрос: «Что фактически изменилось в проекте?»

Журнал не является дословной стенограммой. В него переносятся только сведения,
которые нужны для восстановления контекста и продолжения работы.

## Жизненный цикл

1. Фазы 1 и 2 проходят без изменения репозитория.
2. После согласования модели и явного разрешения на реализацию создаётся рабочая
   ветка.
3. Первым содержательным изменением в ветке создаётся журнал по шаблону.
4. В журнал переносятся исходный запрос, анализ, существенные вопросы, решения,
   согласованное задание и подтверждение пользователя.
5. Во время реализации добавляются выполненные действия и проверки.
6. После `commit` и `push` ветка передаётся пользователю для Pull Request и Merge.

## Статусы вопросов

- `открыт` — ответ ещё нужен до продолжения соответствующего этапа;
- `решён` — решение принято и записано;
- `отложен` — вопрос не блокирует текущую работу и имеет точку возврата.

## Возобновление

Чтобы продолжить сохранённую работу, пользователь пишет:

```text
/resume WP-003
```

Агент читает `AGENTS.md`, `WORK_PLANS.md` и соответствующий журнал, затем
восстанавливает состояние и продолжает с первой незавершённой точки. Команда не
заменяет отдельного подтверждения на переход к реализации.

## Имена файлов

Используется формат:

```text
docs/discussions/WP-NNN-краткое-название.md
```

Новый журнал создаётся на основе `docs/discussions/TEMPLATE.md`.
